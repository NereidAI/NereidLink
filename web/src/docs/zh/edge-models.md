# 边端模型

**边端模型**标签页出现在 hello 握手中协商了 `inference` 能力的[网关](help:glossary/gateway)设备上（ADR-0039）。它展示网关上实际存在的 AI 模型，并允许通过通用的 `edge-inference` 连接器把摄像头（子设备）绑定到某个模型。

NereidLink 不存储、也不中转模型文件：它只保存网关上上报的库存、进行展示，并在模型或推理运行时不健康时产生告警。

## 三个状态平面

模型推理健康状况分三个相互独立的平面展示，某个平面异常并不代表其他平面也异常。

1. **推理运行时**——边端的推理服务进程（例如兼容 KServe/OpenAI 的运行时）。状态取自网关[设备影子](help:device-shadow) reported 中的 `inference` 块：`ONLINE`、`DEGRADED`、`OFFLINE`，或在超过三个探测周期未收到健康上报时显示为**未知 / 过期**。页面保持打开期间会通过完整设备影子的 WebSocket 事件持续更新缓存中的健康上报；正常运行时无需切换页面或手动刷新。卡片还会显示就绪/总模型数、活动绑定数以及最近一次上报的延迟。
2. **模型库存**——网关最近一次上报的模型，每个模型有独立的生命周期状态。
3. **绑定**——本网关上的 `edge-inference` 连接器实例及其上报的连接器状态（`APPLIED`、`DEGRADED`、`FAILED`……）。

## 模型库存

网关在 manifest 的 `models` 段中上报完整模型列表。每次上报都是**全量替换**：新列表中缺失的模型会被删除；显式上报空列表表示网关当前没有任何模型。不发送该段的旧固件不会改动已保存的库存。

每一行展示：

- **模型**——模型 id、语义版本、构建 revision 以及运行时模型名。
- **任务 / 族**——任务族（如 `detection`）以及任务内的结果/后处理族（如 `yolov8`）。
- **模型服务器**——实际驱动该模型的服务器。上报具体模型服务器产品的固件会显示其族标识（如 `ovms`、`triton`、`external`），并在其下方附推理协议族（`kserve`、`openai`、`task-runtime`）；旧固件只知道协议族时则单独显示协议族。协议族是通信协议，不是厂商名或实例名。
- **状态**——取值之一：
  - `EXTRACTING`——模型包正在解压。
  - `VALIDATING`——模型正在校验。
  - `READY`——可用于绑定。
  - `FAILED`——模型失败；把鼠标悬停在状态标签上可查看传输安全的原因码。
  - `REMOVED`——边端已报告移除。
- **类别标签**——模型的类别名，按原样保存与展示，平台不做任何解释或翻译。
- **绑定数**——引用该模型的 `edge-inference` 实例数量。

### 库存过期

有两种情况会把库存记录标记为**已过期**，记录都会保留（不删除）并显示过期标签，直到网关再次上报 models 段后清除：

1. 网关完全停止发送 manifest（manifest 租约过期）；
2. 对于已经上报过模型的网关，manifest 仍在周期到达（其他页签正常），但 `models` 段连续超过 15 分钟缺省——例如推理服务已清空，而边缘没有发送权威的空清单 `"models": []`。

已过期的模型不能被选用于新的绑定。若运行时卡片显示 0/0 而库存行仍无过期标记，通常意味着边缘固件未按契约上报，应检查边缘侧。

## 把摄像头绑定到模型

点击**绑定推理**即可在一个操作中完成检测绑定。只有当网关上报了至少一个未过期的 `READY` 模型时按钮才可用。

向导会：

1. 让你选择**数据源摄像头**（网关管理的某个子设备）、**取流方式**和一个 **READY 模型**。
2. 创建一台名为 `inference:<源设备>[:profile-<码流配置哈希>]:<模型 ID>:<模型版本哈希>` 的**虚拟输出子设备**，它引用平台内置、对租户可见的 `detection/v1` 系统 profile。只有显式选择 ONVIF 码流配置时才包含 profile 段；使用摄像头默认码流时仍沿用不含该段的旧名称。托管摄像头绑定身份由“摄像头 + 码流配置 + 模型 ID/版本”组成：同一码流配置可以并行运行多个模型版本，不同码流配置也可以独立运行同一个模型版本。精确重绑会复用保留的输出设备，包括在引入码流配置感知命名之前创建的设备。输出遥测测点（`detection_count`、`top1_label`、`top1_score`、`infer_latency_ms`、`detections_json`）承载推理结果。直连 URL 的名称由 URL 和模型版本确定（`inference:url:<主机>-<URL 哈希>:<模型 ID>:<模型版本哈希>`），因此同一个 URL 也可以并行绑定多个模型版本。向导根据摄像头名称（或直连 URL 主机）和 `model.id@version` 生成可编辑的**输出子设备别名**。别名仅是显示元数据，不参与绑定身份判断；重新绑定已有设备时默认保留原别名，手动修改后才会更新。
3. 在网关上创建一个绑定到该子设备的 `edge-inference` 连接器，其 `model_ref` 指向所选模型的 id/版本，并带**推理设备**（`target_device`）、取流方式与触发设置。如果相同“数据源（包括 ONVIF 码流配置）+模型 ID+版本”已经绑定，向导会更新现有连接器并递增 revision，而不是重复创建；另一个码流配置或模型版本会创建独立绑定。

**推理绑定**表格会直接区分并行推理流：每一行都显示输出设备别名和 canonical name、完整的绑定模型 ID、醒目的完整模型版本标签以及模型构建 revision，同时显示取流方式、推理设备和连接器状态。请通过模型列识别绑定，不要依赖可能自定义过的别名；状态列表示该期望绑定是否已应用、降级或失败。

**取流方式**决定每一帧从哪里来：

- **抓拍 JPEG**（默认）：边缘每周期调用一次摄像头的 ONVIF `Snapshot` 命令，只推理这一张 JPEG。开销小，但拍不到两次抓拍之间的画面。
- **视频流（RTSP）**：边缘根据摄像头的 ONVIF 注册信息在**本地解析** RTSP 地址（URL 和凭据不离开网关，也从不上云存储），保持 ffmpeg 订阅，每个触发节拍取最新一帧推理。该模式下会出现**码流配置**选择器：通过边缘只读操作枚举摄像头的 ONVIF 媒体配置（主/子/第三码流及分辨率、编码和帧率），留空表示摄像头默认（通常是主码流），也可以手动填写 token。摄像头没有可用 RTSP 时上报 `source-no-frame`，不会偷偷回退抓拍。视频流与码流选择仅在网关自注册连接器 schema 声明支持时可见，旧固件不显示。
- **直连 URL（非 ONVIF）**：面向完全没有 ONVIF 注册的摄像头/编码器——直接按地址绑定。选择**传输方式**（RTSP over TCP、RTSP over UDP、Motion JPEG（HTTP）或单帧 JPEG（HTTP）），填写**摄像头 URL**（RTSP 类用 `rtsp://host/...`，MJPEG/JPEG 用 `http(s)://host/...`，最长 1024 字符）。**不要在 URL 中填写用户名或密码**——该地址会保存在平台中。摄像头需要认证时，先由运维在边缘推理服务的密钥库中创建命名密钥（用户名/密码），向导里通过可筛选的**边缘密钥名称**下拉选择——下拉列出已下发到本网关的密钥（设备详情的**密钥**页），仅在边缘预置、平台不知道的名称也可直接输入；密码不离开网关。摄像头支持 ONVIF 时请优先使用抓拍/视频流。协议不匹配、内嵌凭据、地址不可达或 401 都会被明确拒绝（应用时 `config-invalid`，运行时 `source-no-frame`），不会偷偷切换取流方式。

**触发方式**控制推理频率：**事件触发**在按需读取/自检时推理，并带最大空闲保护；**周期触发**每 `period_ms` 推理一次；**连续触发（FPS）**按稳定帧率推理（0.1–60 FPS，默认 5），是视频流的典型搭配。连续选项同样仅在固件 schema 枚举包含它时出现。

**高级选项**（边缘固件声明支持时显示）：

- **附带证据图片**（`emit_frame`，默认开）：每条结果事件都附带标注后的证据 JPEG。关闭可省上行带宽与存储，但结果下钻没有图片。
- **图片/预览画框**（`annotate_preview`，默认开）：在证据图片和本地诊断预览上绘制检测框与标签；与是否附带图片相互独立。
- **自定义 ffmpeg 参数**（`ffmpeg_extra`，视频流与直连 URL）：取流附加的 argv 片段，空格分隔、无 shell 无引号。仅接受 `-re` 与带值的 `-r`/`-ss`/`-t`/`-threads`/`-fflags`/`-flags`，例如 `-fflags nobuffer -flags low_delay`；其他参数在应用时被边缘拒绝。
- **硬件解码**（`decode_accel`，仅 ONVIF RTSP 视频流及直连 `rtsp`/`rtsp-udp`）：软件解码为缺省且不发送新键。选择 **VA-API 硬件解码**会发送 `decode_accel=vaapi`；快照、MJPEG、JPEG 源不提供该选项。**GPU 设备**可选择 `renderD129`、`renderD130`，或自定义 `renderD<N>`/`/dev/dri/renderD<N>` 节点（`vaapi_device`）；默认项不下发该字段，由 NI 使用 `/dev/dri/renderD128`。这些站点本地管线属性不进入模型包，也不通过 `ffmpeg_extra` 表达。边缘主机必须预先提供 VA-API 驱动（例如 `intel-media-driver`）和 `/dev/dri` 访问（容器设备映射或 Kubernetes `gpu.intel.com/i915`）。设备或驱动缺失时作业会明确失败，**不会自动回退软件解码**。

**推理设备**是绑定期的运维部署决策，不属于模型包。可从预设选择（`CPU`（默认）、`GPU`、`GPU.0`/`GPU.1`/…（指定加速器索引）、`NPU`、`AUTO`），也可手填 `MULTI:GPU,CPU`、`HETERO:GPU,CPU` 等 OVMS 复合形式（仅允许字母、数字与 `_.:,-`，最长 64 个字符）。它是硬要求：边缘必须在该设备上正确出结果，做不到时必须显式上报失败（`target-device-unavailable`），**不会**静默回退 CPU。不含该字段的旧绑定等价于 `CPU`。只有当网关的边缘固件在自注册的连接器 schema 中声明了该属性时，向导才允许选择；旧固件该字段锁定为 `CPU` 并提示升级。

如果连接器创建或更新失败，向导会自动删除刚刚创建的输出子设备，不会留下孤立设备。解绑后用相同“数据源+模型 ID+版本”重新绑定时，会通过重新激活复用被保留（停用、召回窗口内）的输出设备，未手动编辑时保留其原别名。写入决策使用实时重新获取的连接器和设备状态；如果已有绑定引用的输出设备不存在，向导会停止并要求先解绑失效绑定，而不是创建孤立的替代设备。后续删除绑定走正常的连接器生命周期；除了本向导中的 READY 前置检查外，Phase A 不在服务端对 `model_ref` 做额外校验。

## 告警

平台产生以下去重告警，条件恢复时各自自动清除：

- **`GATEWAY_MODEL_FAILED`**（重要）——每个上报为 `FAILED` 的模型一条。
- **`GATEWAY_MODEL_STALE`**（警告）——manifest 租约过期，或 `models` 段连续静默超过 15 分钟期间，每个网关一条；下次成功上报模型后清除。
- **`GATEWAY_INFERENCE_RUNTIME`**——运行时上报 `OFFLINE` 时为重要；健康块超过三个探测周期静默时为警告。
- **`GATEWAY_CONNECTOR_FAILED` / `GATEWAY_CONNECTOR_DEGRADED`**——绑定平面复用的通用连接器告警；`DEGRADED`（警告）覆盖诸如 `idle-no-inference` 之类的情况。

## 权限与接口

- 查看库存需要 **connector:read** 权限：`GET /v1/tenants/{tenant}/gateways/{gateway}/models`，无模型的网关返回 `[]`（绝不会是 `null`）。
- 视图通过唯一的控制台 WebSocket 实时更新；绑定使用现有的设备创建与连接器创建/更新权限。
