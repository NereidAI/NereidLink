# 伴生服务端点

伴生服务端点用于注册一个外部伴生服务安装（例如人脸门禁或抄表服务），该服务通过 `companion-subscription/v1` 合同消费边缘推理事实。NereidLink 为该合同提供唯一的通用连接器：接入新伴生服务只需要注册端点并通过一致性测试，平台代码无需任何改动。

## 连接器的职责边界

- 端点注册信息：伴生服务 ID、目标网关、基础 URL、合同版本，以及每次请求携带的 Bearer 令牌。
- 业务编排部署产生的期望订阅集合，每个源设备一行。
- 伴生服务回报的读回状态（PENDING 等待中、APPLIED 已应用、FAILED 失败），以及单调递增的版本号和失败原因。

NereidLink 不存储任何伴生服务的业务数据——不存照片、特征向量、人脸库、人员或台账。这些数据只保留在伴生服务与客户主数据系统中。

## 注册端点

打开 **配置 → 伴生服务端点 → 注册端点**，填写：

- **伴生服务 ID（Companion ID）** —— 业务装配节点使用的逻辑 ID（例如 `face-service`）。小写 slug，创建后不可修改。
- **网关 ID（Gateway ID）** —— 目标网关设备名，同样不可修改；同一伴生服务接入另一网关时需要新建独立端点。
- **基础 URL（Base URL）** —— 伴生服务的绝对 http(s) 根地址。任何非回环部署都应使用 https。
- **Bearer 令牌** —— 按伴生服务安装签发。该字段只写不读：界面只显示是否已存储令牌，不回显令牌内容。编辑时留空表示保留原令牌；清空后保存表示移除令牌。
- **跳过 TLS 证书校验** —— 仅用于内网 CA 未被主机信任的实验室 https 端点；正式环境应正确信任 CA。

重复注册相同的伴生服务 ID 与网关会更新原记录，而不是产生重复端点。

## 期望订阅与读回

眼睛图标可查看单个端点的期望订阅表。每行展示源设备、流水线、结论设备，以及伴生服务最近回报的状态与版本号。业务编排每次部署都会全量替换期望集合：新集合中缺失的行会被退订，实例下线时只删除该实例拥有的行。

只要存在 FAILED 行，部署就不会报告成功。失败原因采用伴生服务返回的稳定 kebab-case 代码；修复伴生服务侧问题后重新部署即可。若伴生服务无法在 `GET /api/v1/version` 声明期望的合同版本，连接器会在写入任何订阅之前直接拒绝。
