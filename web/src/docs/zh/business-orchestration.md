# 业务编排

[业务编排](help:glossary/business-orchestration)用于装配现有资产，不执行摄像头帧，也不替代 NereidInference 的 pipeline 注册与技术编排。

## 模板与实例

**模板**页签列出不可变的[业务模板版本](help:glossary/business-template-version)。平台本身不携带任何业务词汇：模板版本只存在于租户内，来源是模板包导入或设计器发布。点击**导入模板包**可上传 YAML 或 JSON 模板包（单个模板文档，或 `{"templates":[...]}` 封装），点击**新增模板**可从空白装配开始。填写唯一的 ID 和版本，编辑业务画布及标量参数 JSON Schema 后保存。点击**导出模板包**可将当前租户的全部模板下载为一个可移植 YAML 包。参考模板包（**人脸门禁 `0.0.1`** 与**工业抄表 `1.0.0`**）以数据文件形式位于 `samples/business-templates/`，不再编译进二进制。

点击任意卡片的**编辑**会加载原文档、固定模板 ID，并将修改发布为新的不可变版本。设计器会建议下一个补丁版本，也可以在保存前修改。已有实例仍固定使用原快照。点击**删除**并确认后，可删除未被引用的版本；只要仍有实例引用，服务器就会返回 `409` 并拒绝删除。要删除已引用版本，必须先撤消部署并删除所有引用它的实例；删除实例不会删除其模板版本。

点击版本卡片上的**创建实例**并填写名称，会在**画布**页签打开独立草稿。保存草稿后创建的[业务实例](help:glossary/business-instance)保留完整原模板快照，后续发布新模板版本不会改变它。每次保存的期望修订形成一个[业务代次](help:glossary/business-generation)。模板可以包含未绑定的资产占位；部署前必须选择装配要求的真实摄像头、模型、伴生服务结论设备、命令和转发器。人脸建档与表计标定仍由对应伴生服务负责。

参考模板包**人脸门禁 `0.0.1`**包含两个独立模型依赖：**人脸检测**（YuNet）和**人脸特征**（SFace）。必须在目标网关上分别选择具体的 READY 模型 ID／版本；人员建档不会按人增加模型。NI 负责检测解码、五点对齐、裁剪组批和特征事实输出，`face-service` 负责建档、人脸库和 1:N 匹配。NL 中这两个模型节点不定义 NI pipeline 拓扑。

## 装配画布

从左侧拖入资产，并按业务关系连线：

- 摄像头到 pipeline；
- 模型或外部 servable 到 pipeline；
- pipeline 到伴生服务或规则；
- 伴生服务到规则或北向出口；
- 规则到动作或北向出口。

连线仅表示订阅或触发关系，不要在画布中绘制检测、裁剪、OCR、embedding 等逐帧阶段。

选中节点后编辑资产引用。摄像机节点会加载现有活动网关，并列出所选网关管理的设备；输出设备也使用同一联动设备目录。切换或清空网关会清空之前的摄像头和输出设备选择。如果下拉列表为空，请先在**设备**页面创建网关或受管摄像头。源类型、解码加速和发布模式使用封闭下拉；目标设备预设值仍允许填写自定义 OpenVINO 目标。

模型和伴随服务选择器根据摄像机到管线的连接，以及模型／伴随服务与管线的关系推导目标网关。只有每个目标网关上都存在且未过期的 READY 模型 ID／版本才可供选择，版本列表随模型 ID 联动。只有每个目标网关上都注册了已启用端点的伴随服务才可供选择。修改这些连接或摄像机网关会清空受影响的模型 ID／版本或伴随服务选择。结论设备和命令目标来自活动设备注册表。

动作类型使用封闭下拉。**下发命令**先显示目标设备，再显示该目标已声明并启用的命令；切换目标会清空命令。**创建告警**则显示告警类型，以及 `CRITICAL`、`MAJOR`、`MINOR`、`WARNING` 四个封闭严重级别。北向输出列出当前租户已启用的转发器。当前目录中不存在的旧引用仍会保留显示，以便检查和修复导入的草稿，但不代表它仍可部署。

管线 ID 仍是精确的手输引用，因为当前控制台没有权威管线目录。原始 EdgeX 设备／profile／资源名称同样保留精确手输，而不是伪造下拉选项。在参数区域填写标量模板参数。编辑已有实例时，**保存草稿**会发送预期代次，防止旧编辑器覆盖他人修改。

**校验**显示文档和实时模型问题。**预览展开**显示已保存代次的确切声明式产物与确定性摘要，详见[业务展开](help:glossary/business-expansion)。**校验**、**预览展开**和**部署**都会先保存画布中的待保存修改，不会作用于旧的已保存装配。

## 发布与隐私

`PublishMode` 和 `PublishReadings` 只控制 NI 本地事件发送，不代表北向上传。只有显式添加北向节点、选择已有转发器和结论字段，并填写目标网关实际上报的精确原始 EdgeX 设备名、profile 名和资源名，才会声明上传。NereidLink 绝不会根据自身设备 UUID 或规范名称推导这些 EdgeX 名称。

读数白名单与 EdgeX 资源白名单都必须显式声明。北向上传不能使用通配符、`PipelineJSON`、embedding 路径或大小写敏感的 `Embedding*` 资源。展开时，每个北向节点仍是一个通道贡献；NereidLink 会根据所有 active 或 pending 业务实例，计算出一个网关级 `edge-northbound-filter` 单例。该过滤器使用原始 EdgeX 名称和有序 allow/deny 规则；没有任何贡献后会被静默，而不是删除。`channel` 只是封套元数据，转发器仍负责选择 JetStream stream 和 sink。伴生服务消费的绑定不能使用 `PublishMode=nonempty`，外部 servable 绑定不能设置 `TargetDevice`。

## 部署与监控

部署会在任何 NL 资源变更前预检所有目标能力。pipeline、伴生服务或传输能力缺失时，部署失败，不会显示部分成功。连接器、规则链、设备绑定和转发器仍由原资源所有者管理。

**实例**页签显示期望、待生效与生效代次，以及校验问题、健康状态、回滚和撤消部署操作。只有通过健康回读的代次才会生效。回滚使用保留的展开快照。撤消部署只删除实例拥有的资源，不卸载共享模型，也不删除伴生服务和转发器。

点击实例的**监控**可读取每个摄像头的健康状态。只有运行时真实上报时才显示 P50/P95 延迟和事件速率。“不可用”表示没有权威读数，不代表数值为零。

## 当前 M3 限制

pipeline 和仅引用式外部 servable 展开物使用已回签的 `edge-manager-resource` v1 连接器契约，必须取得当前 manager 观察回读后才能判定健康。在 NI 提供 runtime-only 的对称资源前，托管外部 servable definition 仍会被阻止；伴生服务订阅格式不可用时，依赖伴生服务的装配部署同样会被阻止。保留的旧开发快照若包含扁平 manager 展开物，则属于无效快照，必须另存为新生成的展开代次，不能用于回滚或部署。集成细节见[网关集成](help:page/integrate-gateway)指南以及 NereidLink `docs/` 中的设计与回签文档。
